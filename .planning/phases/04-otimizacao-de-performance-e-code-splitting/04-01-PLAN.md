# Plan 04-01: Otimização de Performance e Code-Splitting

## Contexto & Objetivos

No build atual, o bundle inicial da aplicação ultrapassa 2.3MB (`index-*.js`) porque bibliotecas pesadas de 3D e física (`three`, `@react-three/fiber`, `@react-three/cannon`, `@react-three/drei`), bem como componentes secundários (Livros de Regras, GM Screen, Bestiário, Rolador de Dados 3D), são importados estaticamente no ponto de entrada `src/App.tsx`.
Nesta fase, configuraremos a divisão inteligente de chunks no Rollup (`manualChunks` no `vite.config.ts`) e implementaremos carregamento dinâmico (`React.lazy` e `<Suspense>`) no frontend, atingindo um tempo de inicialização expressivamente mais rápido e chunks leves ideais para hospedagem em CDNs gratuitas (Vercel/Netlify).

## Requisitos Cobertos

- **OPT-01**: Configuração de `manualChunks` no `vite.config.ts` para isolar Three.js e Cannon (`three`, `@react-three/fiber`, `@react-three/cannon`, `@react-three/drei`) em chunk próprio.
- **OPT-02**: Carregamento sob demanda (*code-splitting* / lazy loading) dos componentes 3D e modais pesados, garantindo carregamento inicial ultrarrápido.

---

## Passos de Execução

### Passo 1: Configuração do `vite.config.ts` com `manualChunks`
- Adicionar configuração de `build.rollupOptions.output.manualChunks` categorizando:
  - `three-vendor`: Three.js, React Three Fiber, Cannon e Drei.
  - `ui-vendor`: Lucide icons e React Player.
  - `db-vendor`: Dexie e Dexie React Hooks.
  - `network-vendor`: Socket.io client.
- Ajustar `chunkSizeWarningLimit` adequadamente para chunks de vendors pesados se necessário.

### Passo 2: Code-Splitting e Lazy Loading em `src/App.tsx`
- Converter componentes pesados para `React.lazy`:
  - `DiceOverlay` e `DiceSidebar` (que puxam Three.js/Cannon)
  - `CharacterSheet`
  - `PlayerRulebook` e `GMRulebook`
  - `GMScreen`
  - `BestiarySidebar`
- Envolver as renderizações com `<Suspense fallback={<LoadingSpinner />}>` para transições visuais suaves sem travamento da interface.

### Passo 3: Verificação de Build e Métricas de Tamanho
- Executar `npm run build` (`tsc -b && vite build`).
- Confirmar que o chunk principal da aplicação caiu substancialmente (para menos de 500kB) e que `three-vendor` foi extraído para um arquivo isolado.
- Validar se todos os testes (`npm run test:server` e `npm run test:storage`) continuam operacionais.
